# Дизайн: конфигурация инструментов

Issue: https://github.com/42-Z/Mimic42/issues/37
Дата: 2026-10-01

## Цель

Дать пользователю включать и выключать инструменты Мимика, а пресетам — задавать
не только промпт, но и набор доступных инструментов. Это решает три задачи из
issue: модель перестаёт путаться в 91 инструменте, для отдельных сценариев не
нужны лишние возможности, а поведение бота можно ограничить осознанно.

## Контекст (по коду)

- Каталог инструментов — фиксированный список из 91 `StructuredTool`:
  `build_telegram_langchain_tools` в `src/mimic42/integrations/telegram_tools.py:2832`.
  Произвольного вызова метода Telethon среди инструментов нет: отключение имени —
  это отключение конкретного инструмента, а не действия вообще.
- Полный список безусловно попадает в `create_agent(tools=...)`
  (`manager.py:286,322` → `langchain_agent.py:132-140`).
- `AgentRuntimeConfig` (`agent_runtime.py:102-116`) не знает о настройках
  инструментов; `DatabaseAgentStore.get_runtime_config`
  (`database_agent_store.py:169-211`) извлекает из `agents.settings` только
  `model`, `reasoning_effort`, `first_comment`.
- Обычный ответ в диалог и «Первый комментарий» отправляются рантаймом напрямую
  (`agent_runtime.py:584-697, 849-926, 1061-1092`), это не вызовы инструментов.
- Сохранение «Настроек» — merge в `agents.settings` плюс `agentsApi.reload()`
  (`TabSettings.tsx:72-105`, `manager.py:213-238`). Для остановленного агента
  конфиг подхватывается при следующем запуске.
- `agents.settings` уже доступна клиенту на чтение и (по колонкам) на запись:
  `grant update (name, soul_prompt, settings, updated_at)` в
  `supabase/migrations/20260925184227_harden_onboarding_session_access.sql:89-90`.
- Фронтенд уже ведёт человекочитаемый каталог имён (история действий):
  `frontend/src/lib/activity/toolCatalog.ts:103-214` — 91 запись, 10 групп,
  русские подписи в прошедшем времени.
- Пресеты — таблица `public.prompt_presets` (`20260920085947_add_prompt_presets.sql`),
  только `select` под `authenticated`; пикер отдаёт наружу только `body`
  (`PresetPicker.tsx:12-18,86-94`). Онбординг применяет пресет в черновик
  (`agent_onboarding_sessions`), финализация сохраняет только имя и характер
  (`onboarding.py:376-397`, `useOnboarding.ts:133-143,208-223`).

## Принятые решения

| Вопрос | Решение |
|---|---|
| Формат настройки | `agents.settings.enabled_tools: string[]` — allowlist. Ключа нет — включены все (совместимо с существующими агентами). Пустой список — не включён ни один инструмент |
| Единица настройки | Имя инструмента из каталога. Группы — только навигация в интерфейсе, отдельной сущностью не являются |
| Где ограничение действует | Два уровня: отфильтрованный список в `create_agent` (модель не видит отключённое) и middleware — второй барьер: имя вне allowlist не исполняется, даже если оно пришло не из отфильтрованного списка |
| Обычные ответы | Не инструменты: отключение любого инструмента не мешает боту отвечать в диалоге и отправлять первый комментарий |
| Каталог и тексты | Фронтенд получает у каталога действий нейтральные `title`/`description`; инструмент, которого нет в каталоге фронта, не показывается, но его имя сохраняется при записи настроек |
| Сохранение | Та же форма «Настройки»: dirty → «Сохранить изменения» → merge в settings → `agentsApi.reload()`. Память и контекст не сбрасываются |
| Пресеты | `prompt_presets.settings jsonb` — частичный патч настроек агента. Применение пресета подставляет `enabled_tools` в форму; в базу пишет только общий Save |
| Онбординг | Черновик получает колонку `settings jsonb`; выбранный на шаге «Характер» пресет переносит настройки инструментов в создаваемого агента |
| Сид | `rage_comments` получает курируемый allowlist инструментов комментатора; остальные пресеты — без настроек |
| Промпт | `BASE_SYSTEM_PROMPT.txt` не переписываем: абзацы про конкретные инструменты не мешают, когда инструмент отключён |

## Схема данных

Одна миграция `supabase/migrations/20261001HHMMSS_tool_configuration.sql`
(имя и время создаёт Supabase CLI, файл не сочиняем руками).

```sql
-- Пресеты: частичный патч настроек агента.
alter table public.prompt_presets
    add column settings jsonb;

alter table public.prompt_presets
    add constraint prompt_presets_settings_is_object
    check (settings is null or jsonb_typeof(settings) = 'object');

-- Пример курируемой конфигурации: комментатору нужны только каналы,
-- обсуждения, реакции и проход капчи в обсуждении.
update public.prompt_presets
set settings = jsonb_build_object('enabled_tools', jsonb_build_array(
    'get_dialogs', 'get_messages', 'search_messages',
    'get_discussion_messages', 'join_channel_discussion',
    'view_image', 'send_text_message', 'send_chat_action',
    'send_reaction', 'get_message_reactions', 'mark_chat_as_read',
    'get_chat_info', 'check_admin_permissions',
    'get_message_buttons', 'click_inline_button', 'start_bot'
))
where slug = 'rage_comments';

-- Черновик онбординга: настройки будущего агента.
alter table public.agent_onboarding_sessions
    add column settings jsonb not null default '{}'::jsonb;

alter table public.agent_onboarding_sessions
    add constraint agent_onboarding_sessions_settings_is_object
    check (jsonb_typeof(settings) = 'object');

-- Колоночные гранты визарда: добавляется ровно одна безопасная колонка,
-- это тот же класс данных, что agents.settings, которая и так writable.
-- Прежние колоночные гранты не отзываются — новые привилегии накапливаются.
grant insert (settings) on table public.agent_onboarding_sessions to authenticated;
grant update (settings) on table public.agent_onboarding_sessions to authenticated;
```

`grant select` на `prompt_presets` уже табличный, новая колонка попадает в него
автоматически. После миграции — `bun run generate:types`, чтобы
`frontend/src/types/supabase.ts` увидел обе колонки.

## Семантика и бэкенд

**Разбор настройки.** Новый модуль `src/mimic42/core/tool_config.py` по образцу
`core/first_comment.py`:

```python
def parse_enabled_tools(raw: Any) -> frozenset[str] | None:
    """None — ключа нет, включены все. Иначе — allowlist."""
```

- `None`/отсутствие → `None` (все инструменты);
- пустой список → пустой allowlist (ни один инструмент не включён);
- непустой список: строки обрезаются, пустые и нестроковые элементы
  отбрасываются. Если валидных строк не осталось — это мусор → `None` (все
  включены), а не случайное «выключить всё»;
- любой другой тип (не список) → `None` и запись в лог: нечитаемая настройка
  не должна кирпичить агента.

**Конфиг.** `AgentRuntimeConfig` получает поле
`enabled_tools: frozenset[str] | None = None`; `get_runtime_config` читает его из
`agent.settings.get("enabled_tools")`. `OnboardingService.build_runtime_config`
(в онбординге гоняется на черновике) остаётся с дефолтом — все инструменты.

**Фильтрация.** `build_telegram_langchain_tools` получает параметр
`enabled_tools: frozenset[str] | None = None` и возвращает
`[t for t in tools if t.name in enabled_tools]`, когда набор задан. Оба
вызова в `manager.py` передают `config.enabled_tools`. Существующий тест на 91
инструмент не меняется — вызов без параметра даёт прежний каталог.

**Страховка исполнения.** В `build_langchain_agent` при заданном allowlist
добавляется middleware `ToolAccessMiddleware` в список раньше
`ActivityMiddleware` — внешним слоем, чтобы заблокированный вызов не попадал
в ленту активности:
`awrap_tool_call` проверяет имя и на отключённый инструмент возвращает
`ToolMessage(status="error")` с текстом «Инструмент отключён в настройках
агента» и именем инструмента.

Это второй барьер инварианта «отключено — не выполняется»: каталог уже
отфильтрован при сборке рантайма, а guard отклоняет имя вне allowlist
независимо от того, откуда оно пришло — скажем, модель назвала несуществующий
инструмент или появился путь сборки без фильтра. На заблокированный вызов
модель получает единый ответ guard — включая имена, которых нет в каталоге;
сообщение `ToolNode` со списком доступных инструментов в этом случае не
показывается. Окно гонки на reload он не закрывает: middleware держит тот же
снимок allowlist, что и каталог, а доживающий ход старого рантайма живёт с
прежним снимком.

**Чего ограничение не делает.** Инструменты пересекаются по действиям
(`send_file` умеет стикеры и кружки, `click_reply_keyboard_button` может
отправить текст, `set_chat_banned_rights` пересекается с `ban_chat_member`),
но настройка управляет инструментами, а не семантическими «способностями», и
мы это явно фиксируем. Рантайм-отправка ответов и первого комментария — не
инструменты и не ограничивается.

## Каталог и тексты

Метаданные настроек живут в новом файле `frontend/src/lib/tools/toolInfo.ts`:
упорядоченный массив `TOOL_INFO` (имя, группа, `title`, `description`) и
`TOOL_GROUP_ORDER` — фиксированный порядок групп: Сообщения, Диалоги и поиск,
Каналы и обсуждения, Медиа, Стикеры, Профиль и контакты, Информация о чатах,
Участники, Настройки чата, Создание и удаление, Разное, Папки чатов, Боты и
кнопки, Приватность и аккаунт. Каталог истории действий
`frontend/src/lib/activity/toolCatalog.ts` не перестраивается: оттуда берутся
иконки для строк. Синхронность двух списков стережёт тест `tool-info.test.ts`
(91 имя, проверка в обе стороны).

- `title` — нейтральное название возможности: «Отправка сообщений», «Реакции»,
  «Бан участника». `description` — одна строка о том, что инструмент делает.
- Подписи для истории (`ru`) не меняются.
- Тест полноты каталога: 91 запись, все имена уникальны, у каждой есть
  `title` и `description`, группа известна.
- Имена, которых нет в каталоге фронта, в список настроек не попадают, но при
  сохранении формы сохраняются в `enabled_tools` (чтобы не выключить
  инструмент из будущего бэкенда).

## Интерфейс настроек

В `TabSettings` появляется секция «Инструменты» (между моделью и первым
комментарием):

- Заголовок со счётчиком: «Включено N из 91» и кнопка «Включить все» —
  сбрасывает настройку в режим «ключа нет» (все инструменты, включая будущие).
- Поиск по названию, описанию и имени инструмента; при поиске группы
  раскрываются автоматически.
- Десять сворачиваемых групп; в заголовке группы счётчик «N из M» и
  переключатель всей группы. По умолчанию группы свёрнуты.
- Строка инструмента: `title`, `description` и переключатель (role="switch",
  доступное имя — название инструмента).

Переключатель выносится из локального `Toggle` в
`frontend/src/components/agent/FirstCommentSettings.tsx:383-414` в
`frontend/src/components/ui/switch.tsx` и переиспользуется; поведение и вид не
меняются.

Состояние формы: `enabled_tools: string[] | null` (null — режим «все»).
Toggle и групповые переключатели формируют явный список. При сохранении:

- список задан → в `settings.enabled_tools` пишется точный список (интерфейс
  собирает имена через `Set`, поэтому дублей не бывает);
- `null` → ключ `enabled_tools` удаляется из settings.

Секция участвует в общем `dirty` и сохраняется той же кнопкой. Валидация в
`validators.ts`: `enabled_tools: z.array(z.string().min(1)).max(200).nullable().optional()`.

## Пресеты

- Тип `PromptPresetRow` получает `settings: Record<string, unknown> | null`.
- `PresetPicker` меняет контракт на
  `onApply: (preset: { body: string; settings: Record<string, unknown> | null }) => void`.
  Пикер показывает, что пресет настроит инструменты: под телом — строка вида
  «Настроит инструменты: 16 из 91», и предупреждение о замене характера
  дополняется «и настройки инструментов», когда они есть.
- Применение в `TabSettings`: `soul_prompt` заменяется телом, известный ключ
  `enabled_tools` (если массив строк) подставляется в форму; иначе настройки
  инструментов не трогаются. В базу ничего не пишется до общего Save.

## Онбординг

- `OnboardingSessionRow` и модель `OnboardingSession` получают
  `settings: dict | None`; репозиторий читает и пишет колонку.
- `useSaveSoulPrompt` вместе с текстом сохраняет `settings` черновика, если
  пресет их задал.
- `StepSoul`: применение пресета подставляет и текст, и настройки.
- `create_from_onboarding` переносит `session.settings` в `agent.settings`
  создаваемого агента (пустой объект — как раньше, всё включено).
- В финализации участвует только строка черновика; тело запроса
  `POST /onboarding/{id}/agent` не меняется.

  страницей код.

## Чего не делаем

- Семантических «способностей» и зависимостей между инструментами — единица
  настройки одна: имя инструмента.
- Ограничения обычных ответов, первого комментария и памяти — они не
  инструменты.
- Правок `BASE_SYSTEM_PROMPT.txt` под отключённые инструменты.
- Пользовательских пресетов, каталога и магазина (issue #67).
- Сида настроек у остальных трёх пресетов: их наборы — отдельное решение о
  курировании; `rage_comments` получает allowlist как показательный пример.
- API-эндпоинта каталога инструментов: фронтовый `TOOL_INFO` синхронизируется
  тестом с activity-каталогом (`tool-info.test.ts`), а размер каталога 91
  независимо закреплён на бэкенде (`tests/integrations/test_telegram_tools.py`)
  и на фронте; кросс-слойной сверки имён нет — добавление инструмента только на
  бэкенде потребует синхронной правки `TOOL_INFO`.
