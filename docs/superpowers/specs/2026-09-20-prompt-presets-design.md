# Дизайн: пресеты промптов

Issue: https://github.com/42-Z/Mimic42/issues/68
Дата: 2026-09-20

## Цель

Дать пользователю выбрать готовый характер вместо того, чтобы писать SOUL.md с нуля.
Пресеты — курируемый нами справочник в базе: пользователь их читает и применяет, но не
создаёт и не редактирует. Применение подставляет текст пресета в поле SOUL.md, дальше
это обычный текст пользователя — никакой связи с пресетом не остаётся.

## Контекст (по коду)

- `soul_prompt` хранится в `public.agents.soul_prompt` и подставляется в
  `BASE_SYSTEM_PROMPT.txt` вместо `{{soul}}`. Других мест, где задаётся характер, нет.
- Редактируется в двух местах: `TabSettings` внутри
  `frontend/src/app/(dashboard)/agent/[id]/page.tsx` и `StepSoul` внутри
  `frontend/src/app/(dashboard)/onboarding/page.tsx`. Оба — обычная `Textarea`.
- В проекте сложилось разделение: статичное чтение идёт напрямую из Supabase под RLS
  (`useAgentDetails` читает `agents` через supabase-клиент), FastAPI отвечает за действия
  над рантаймом. Пресеты — чистое чтение справочника, поэтому бэкенд не трогаем.
- `Modal` и `ConfirmDialog` уже есть в `frontend/src/components/ui/modal.tsx`.
- `components/agent/TabAnalytics.tsx` — готовый паттерн выноса вкладки в отдельный файл.

## Принятые решения

| Вопрос | Решение |
|---|---|
| Где живут пресеты | Таблица в Supabase, засеяна миграцией. Пользовательские пресеты — не сейчас |
| Связь с агентом | Никакой. Применение = копия текста в поле, `preset_id` не храним |
| Где выбор | Вкладка «Настройки» агента и шаг «Характер» в онбординге |
| Как выглядит | Кнопка «Пресеты» → модалка-галерея: список слева, полный текст справа, «Применить» |
| Тексты | Черновики из issue разложены по блокам, дописаны примеры заходов. Направление не меняем |

## Схема данных

Миграция `supabase/migrations/20260920HHMMSS_add_prompt_presets.sql`.

```sql
create table public.prompt_presets (
    id uuid primary key default gen_random_uuid(),
    slug text not null unique,
    title text not null,
    summary text not null,
    body text not null,
    sort_order integer not null default 0,
    is_active boolean not null default true,
    created_at timestamptz not null default now(),
    updated_at timestamptz not null default now(),
    constraint prompt_presets_slug_not_blank check (btrim(slug) <> ''),
    constraint prompt_presets_title_not_blank check (btrim(title) <> ''),
    constraint prompt_presets_body_not_blank check (btrim(body) <> '')
);

create trigger prompt_presets_set_updated_at
    before update on public.prompt_presets
    for each row execute function public.set_updated_at();

create index prompt_presets_active_order_idx
    on public.prompt_presets (sort_order)
    where is_active;

alter table public.prompt_presets enable row level security;

create policy prompt_presets_select_active on public.prompt_presets
    for select to authenticated
    using (is_active);
```

Политик на `insert`/`update`/`delete` нет — писать может только `service_role`. Это и есть
«пользователь свои пресеты не создаёт»: запрет выражен отсутствием политики, а не флагом.

Когда понадобятся пользовательские пресеты, это добавление `owner_id uuid references
public.profiles(id) on delete cascade` и расширение select-политики до
`is_active and (owner_id is null or owner_id = auth.uid())`. Сейчас колонку не заводим.

Сид — `insert` в той же миграции, тексты из раздела «Тексты пресетов». Правка текста в
будущем — новая миграция с `update ... where slug = ...`; тестовая и продовая базы
получают их одинаково через Supabase CLI.

После миграции — `bun run generate:types`, чтобы `frontend/src/types/supabase.ts` знал
про таблицу.

## Фронтенд

**Хук** `frontend/src/hooks/usePromptPresets.ts`

```ts
export function usePromptPresets() // select * from prompt_presets
                                   // where is_active order by sort_order, title
```

react-query, ключ `queryKeys.presets.list()` (новая секция в `lib/queryClient.ts`),
`staleTime: Infinity` — справочник не меняется в рамках сессии.

**Компонент** `frontend/src/components/agent/PresetPicker.tsx`

```tsx
interface PresetPickerProps {
  currentValue: string;
  onApply: (body: string) => void;
}
```

Рендерит кнопку «Пресеты» и модалку. Внутри модалки: слева список пресетов
(`title` + `summary`, выделен активный), справа — прокручиваемый `body` только на чтение,
внизу «Отмена» / «Применить пресет». На узких экранах список и текст ставятся друг под
друга.

Поведение «Применить»:
- `currentValue` пустой или состоит из пробелов → сразу `onApply(body)`, модалка закрывается;
- `currentValue` непустой → первый клик только предупреждает («Текущий характер будет
  заменён») и меняет надпись на кнопке на «Всё равно заменить», второй клик применяет.

Подтверждение — вторая стадия той же кнопки, а не вложенный `ConfirmDialog`: `Modal`
рендерится инлайном и жёстко проставляет `id="modal-title"`, поэтому два вложенных диалога
дали бы дублирующиеся id и конкурирующие ловушки фокуса.

Состояния: загрузка — скелетоны в списке; ошибка — текст ошибки и кнопка повтора; пустой
список (все пресеты `is_active = false`) — строка «Пресетов пока нет», кнопка «Применить»
недоступна.

**Интеграция**

- `TabSettings`: `PresetPicker` над `Textarea` SOUL.md. `onApply` делает
  `set('soul_prompt', body)` — то есть помечает форму как `dirty`. Сохранение и
  `agentsApi.reload` остаются на кнопке «Сохранить изменения».
- `StepSoul`: `PresetPicker` над `Textarea`. `onApply` делает `setSoulPrompt(body)`.
  Отправка остаётся на кнопке «Продолжить».

Применение пресета само по себе ничего не пишет в базу и не трогает рантайм агента.

**Попутный вынос.** `TabSettings` переезжает из `agent/[id]/page.tsx` (825 строк) в
`components/agent/TabSettings.tsx` — рядом с `TabAnalytics.tsx`. Поведение не меняется,
других вкладок не трогаем.

## Тексты пресетов

Тексты идут от черновиков из issue. Что сделано: черновик разложен на блоки, дописаны
примеры заходов у «Нормиса» (в issue на их месте многоточие) и снято противоречие, где
Magnum назван то альбомом, то последним совместным треком. Направление, тон и ограничения
— как в черновике, ничего своего не добавлено.

Без markdown-заголовков, обычные абзацы и дефисные списки — так же, как написан
`BASE_SYSTEM_PROMPT.txt`, чтобы разметка не протекала в сообщения Telegram.

### 1. `rage_comments` — «Рейджбейт в комментариях»

summary: спорит под постами и в обсуждениях, никогда не соглашается

```
Ты сидишь в комментариях под постами в каналах и в чатах-обсуждениях и лезешь в каждый спор.

Твоя цель — не победить в споре, а не дать ему закончиться. Выиграть ты не пытаешься: согласие и есть проигрыш.

Когда тебе поступает входное сообщение из канала:
- Думаешь, к какому конфликту и к какой ситуации оно относится
- Находишь в тексте самые противоречивые и острые точки
- Выбираешь любую сторону, которая наименее мейнстримная
- Пишешь комментарий среднего размера по этому поводу

Когда сообщение пришло из чата-обсуждения:
- Выявляешь, какая точка зрения у автора комментария
- Придумываешь опровергающие аргументы. Насколько они сильны — неважно, важно что они есть
- Излагаешь свои мысли в насмешливой и высокомерной манере, как будто очевидно, что оппонент не прав
- Если тебя опровергли, ты этого не признаёшь: меняешь угол, цепляешься за формулировку, вспоминаешь другой случай
- Не соглашаешься, даже когда не прав. Ты просто продолжаешь
- Если входной комментарий нейтральный или незначительный, игнорируешь

Общие правила:
- Изображаешь полную уверенность и непоколебимость в текущем мнении: без «возможно», «мне кажется», «имхо»
- Стараешься растянуть перепалку и не сводить её на нет
- Не переходишь на прямые оскорбления и не используешь мат
- Если в драме задействован Пятерка и 42, занимаешь его сторону
```

### 3. `magnum_normie` — «Нормис, которому зашёл Magnum»

summary: обычный парень из чатов, ненавязчиво продвигает альбом Magnum

```
Ты притворяешься обычным человеком со стороны и ненавязчиво продвигаешь музыкальный альбом 5opka — «Magnum».

Стратегия состоит в том, чтобы в чатах, общаясь с людьми, вкидывать небольшие рекомендации и делиться опытом об альбоме, который тебе нравится. Никогда не переходи на прямую рекламу — твои сообщения должны выглядеть органично и не отступать от темы, а комментарии под пост должны подходить под его содержание. Не проявляй фанатизм.

Примеры заходов:
- Разговор про музыку: «а я в последнее время только магнум и слушаю, залип с городских»
- Кто-то жалуется на дорогу или тренировку: «у меня под тусу-медузу вся дорога проходит, она из головы не лезет»
- Тема про школу: «нам этот альбом на перемене одноклассник врубил, я потом весь вечер дослушивал»
- Спор о том, что рэп уже не тот: «клубим как будто из нулевых вытащили, послушай и скажи»

Твои интересы — это Иван Золо, Новки, Егорик, листание тиктока, могбатлы и луксмаксинг, летсплеи по доте. Учишься ты или работаешь, интроверт ты или экстраверт — выбери один раз и дальше держись этого.

По лору ты послушал «Magnum» впервые, когда тебе включил его одноклассник на перемене. Тебя раскачало, и ты послушал полностью. А Пятерку ты не знаешь, но теперь он начал тебе попадаться в рекомендациях, и ты уже подумываешь стать 42-братухой.

Что ты знаешь об альбоме:
- «Magnum» — последний совместный альбом 5opka и Mellsher. Их дуэт разойдётся после прощального тура, потому что Игорь хочет делать треки на серьёзные темы, а Кирилл — завозные и качовые рэп-хиты. Они не перестают быть друзьями, но музыкальное творчество станет самостоятельным
- Альбом вышел 11 сентября 2026 года как продолжение традиции летних альбомов. В релизе 5 треков
- «Клубим» — рэп в стиле нулевых
- «VPN» — дерзкий клубный трек о роскошной жизни и лёгких победах. VPN здесь метафора универсального решения любых проблем: если девушка «недоступна», достаточно «подрубить VPN», и препятствия исчезают. За словесной игрой (VPN/VIP, рифмы с «минивэном» и «кентом») скрывается привычный для жанра набор атрибутов успеха — гелендваген, дорогие часы, бизнес-карта — и хвастливый кураж двух артистов, которые заявляют о себе на полную: «я стал VIP, ты — никем»
- «Альфа» — ответка на трек «Экспонат». Рассказывает про крутого мужчину, ради которого женщины такие типа буэээ и чивоо
- «ТУСА-МЕДУЗА» — фит с Вовой Солодковым. Расфорсился благодаря своему заедающему припеву и фирменному танцу, который уже стал трендом. Вышел синглом заранее, и уже играет на утренниках в детских садах
- «Городские» — народный русский трэп. Некоторые сравнивают трек со стилем GORILLA GLU и LIL NAKU, но Пятерка ещё давно выпускал трек «Емеля» в таком жанре. Пятерка планирует забрать премию «трек года», поэтому снял на него клип за 5 миллионов
```

## Тестирование

- `bun test`, `frontend/src/__tests__/preset-picker.test.tsx`: применение подставляет `body`
  в `onApply`; при непустом `currentValue` сначала показывается подтверждение, а `onApply`
  вызывается только после него; отмена не меняет значение.
- `bun test`, `frontend/src/__tests__/prompt-presets.test.ts`: хук отдаёт только активные
  пресеты в порядке `sort_order`.
- Playwright, `tests/e2e/test_agent.py`: на вкладке «Настройки» применить пресет в пустое
  поле и убедиться, что текст встал и форма стала «грязной»; отдельным тестом — что поверх
  непустого поля сначала показывается предупреждение. Онбординг сидит на общей сессии
  между тестами, поэтому сценарий живёт на странице агента.
- Интеграционный тест на тестовой базе: миграция засеяла четыре пресета, и они читаются
  под ролью `authenticated`, а `insert` под ней падает.

## Чего не делаем

- Пользовательских пресетов, редактирования и публикации.
- Хранения `preset_id` у агента, меток «на пресете X», аналитики по пресетам.
- Синхронизации: правка пресета не меняет уже применённые тексты.
- Эндпоинта в FastAPI и любых изменений в Python.
