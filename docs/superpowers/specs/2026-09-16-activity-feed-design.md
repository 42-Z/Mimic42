# Дизайн: единая лента «Активность» (объединение вкладок логов)

Issue: https://github.com/42-Z/Mimic42/issues/59
Дата: 2026-09-16

## Цель

Заменить две вкладки «Логи» (Активность/Чат) одной лентой «Активность»: единые блоки ходов без
нарушения связности, работающие фильтры, видимые финальные ответы агента и просматриваемые
медиа. Исправить пагинацию ходов на бэкенде и устранить протухание ссылок на медиа
(FileReferenceExpiredError) за счёт сохранения файлов в Supabase Storage.

## Текущие проблемы (по коду)

1. Порядок: `TabLogs.tsx` сортирует newest-first, но внутри блока ход идёт по хронологии
   (сообщение пользователя вверху блока) — два разных направления чтения.
2. Бэкенд `get_conversation` пагинирует после `turns.reverse()`; окна fetch считаются
   эвристикой от количества ходов — стыки страниц теряют и дублируют ходы.
3. Финальные ответы: нормализация фронтенда не разворачивает `structured_response.text`
   для realtime-записей, а ходы, где ответ ушёл через `tool.send_text_message`, вообще
   не содержат `agent_response` — ответы исчезают из ленты.
4. Фильтры «Диалог»/«Тулзы» только прячут часть ленты, ничего не объединяя.
5. Медиа: media-ID с `file_reference` в payload протухает (Telethon
   FileReferenceExpiredError), base64 в логах обрезается `_truncate` до 4000 символов,
   рендера медиа на фронтенде нет — посмотреть нельзя.

## Решение

### 1. Структура раздела

- Вкладка «Логи» переименовывается в «Активность» (id `'logs'` в URL не меняется — старые
  ссылки `?tab=logs` работают).
- Под-вкладки «Активность»/«Чат» удаляются. Один компонент ленты, один источник данных —
  бэкенд-эндпоинт `GET /api/v1/agents/{id}/conversation` (курсорная пагинация).
- Удаляются `TabLogsChat.tsx`, `ConversationThread.tsx`, `ChatBubble.tsx` (+ToolCard).

### 2. Порядок и пагинация

- Блоки newest-first (новые сверху). Внутри блока тоже newest-first: финальный ответ —
  верх блока, ниже тулзы (по убыванию времени), в самом низу — сообщение
  пользователя/триггер. Хронология читается снизу вверх везде.
- Бэкенд: курсорная пагинация `before=<ISO timestamp>`. Окно: сообщения и события со
  `created_at < before`, построение ходов по turn_id/границам (incoming|dashboard_trigger
  открывает ход), сортировка ходов desc, возврат `limit` ходов и курсора
  `next_before` (min created_at среди всех элементов возвращённых ходов). Курсор
  отсекает строго старше — ни дубликатов, ни потерь, ход не разрезается границей
  страницы.
- Порядок элементов внутри блока определяет `created_at` каждого элемента.

### 3. Рендер блока

- Шапка: время, имя собеседника + ID чата (`payload.peer_name` / `payload.peer`),
  имя агента (для триггеров), бейдж ошибки.
- Тело: финальный ответ агента (`agent_response` ИЛИ исходящее сообщение ИЛИ
  `structured_response.text`), тулзы, входящее сообщение, триггер дашборда — все
  отображаются, ничего не теряется.
- Тулзы: компактные строки (иконка каталога, человекочитаемый лейбл, ключевая
  инфа — получатель/имя файла/текст сниппетом, статус, длительность), по клику —
  детали args/result (как в текущей «Активности»). Каталог подписей дополняется,
  сырые имена вида `<tool.send_text_message>` не показываются.
- Lifecycle-события (start/stop/timer) — компактные однострочные блоки.

### 4. Фильтры

- Два режима: «Полный» (по умолчанию — всё) и «Только чат» (тулзы скрыты; блоки только
  с тулзами тоже скрыты). Плюс поиск и авто-скролл к новому (как сейчас).
- Ссылка с дашборда `?tab=logs&filter=errors` заменяется на `?tab=logs`.

### 5. Realtime

- `useRealtimeFeed` остаётся источником живых ходов; realtime-записи нормализуются тем
  же построителем блоков, что и исторические; мерж с историческими, дедуп по
  turn_id/id, сортировка newest-first, авто-скролл если пользователь у верхнего края.

### 6. Медиа в Supabase Storage

- Бакет `agent-media`: private, `file_size_limit = 20971520` (20 МБ). Создаётся
  миграцией Supabase CLI (`insert into storage.buckets ... on conflict do update`).
  Доступ только через бэкенд с service-role ключом; отдельных RLS-политик для
  anon/authenticated нет.
- Новый модуль `src/mimic42/integrations/supabase_media.py`:
  `SupabaseMediaStorage` (upload/open/remove_prefix) на supabase-py
  (`create_client(url, service_key).storage.from_("agent-media")`). Протокол
  `MediaUploader` — в `src/mimic42/core/media.py`, инъекция через `AgentManager` →
  `build_telegram_langchain_tools` / runtime. Конфиг: `SUPABASE_SERVICE_ROLE_KEY`
  (Settings + `.env.example`).
- Путь объекта: `{agent_id}/{uuid4}/{filename}` — коллизий нет, агенту не нужен turn_id
  для записи.
- Точки сохранения:
  - входящие сообщения с медиа: `_process_media_and_text` дополнительно возвращает
    список `MediaFile` (kind, name, mime_type, size, storage_path) — файл скачивается
    в память (`download_media(message, file=bytes)`) и загружается; метаданные едут с
    триггером (`AgentTrigger.media`) в `save_messages` → `payload["media"]` входящей
    строки;
  - `tool.view_image`: после скачивания байты загружаются в Storage, в результат
    добавляется элемент `{"type": "media_ref", "storage_path", "mime_type", "size",
    "name"}` (data URL остаётся для LLM);
  - `ActivityMiddleware._sanitize_result`: data-URL в записываемом результате
    заменяются маркером `{"_omitted": "base64"}` — base64 больше не попадает в логи.
- Эндпоинт `GET /api/v1/agents/{agent_id}/media/{path:path}`: require_user,
  проверка владельца агента, путь обязан начинаться с `{agent_id}/`; отдаёт файл с
  нужным content-type. Фронт запрашивает с JWT (axios) и показывает через object URL.
- Удаление агента: `remove_prefix(agent_id)` — объекты бакета стираются.

### 7. Рендер медиа (фронтенд)

- Компонент `MediaContent` по `payload.media`: фото/стикер — превью `<img>` (клик —
  просмотр в лайтбоксе), голосовое — `<audio controls>`, round — `<video controls>`,
  файл — чип с именем/размером (клик — скачивание).
- Хук `useMediaUrl(agentId, storagePath)`: axios GET с JWT → blob → object URL.

## Проверка

- Юнит-тесты: построение ленты (порядок блоков/внутри блока), фильтры, курсорная
  пагинация бэкенда, сохранение/отдача медиа, санитизация base64.
- e2e: обновить `agent.spec.ts` (без под-вкладок, новые фильтры).
- `uv run ruff check`, `uv run ty check`, `bun run lint`, `bun run typecheck`,
  `bun test`, `uv run pytest`.
- По ходу сверяться с доками Telethon (download_media), Supabase Storage (python
  client, бакеты в миграциях), FastAPI (Response/StreamingResponse).

## Вне скоупа

- Загрузка медиа в бэк-транскрипцию (уже есть), переотправка медиа агентом из логов,
  пагинация с фильтром по типу, точная докрутка при подгрузке старых страниц
  (позиция сохраняется простым пересчётом scrollHeight).
