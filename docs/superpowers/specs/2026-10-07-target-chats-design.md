# Дизайн: настройка целевых каналов

Issue: https://github.com/42-Z/Mimic42/issues/94
Дата: 2026-10-07

## Цель

Дать пользователю включать и выключать чаты и каналы, доступные Мимику. Отключённый
чат для агента не существует: входящие оттуда не запускают ход, инструменты в него
не пишут и не читают его, первый комментарий под его постами не ставится. Если канал
включён, его комментарии (группа обсуждения) тоже доступны.

## Принятые решения

| Вопрос | Решение |
|---|---|
| Правило доступа | Чат доступен, если его ID нет в `disabled_chats`. Новые чаты (вступил в канал, написал незнакомец) доступны автоматически. Режима «новые чаты выключены» нет |
| Формат настройки | `agents.settings.disabled_chats: number[]` — ID отключённых чатов в формате Telethon (`-100…` у каналов и супергрупп, `-…` у обычных групп, положительные у людей и ботов). Ключа нет или список пуст — ограничений нет, как у существующих агентов |
| Миграция БД | Не нужна: `agents.settings` уже доступна клиенту на запись колоночным грантом (`20260925184227_harden_onboarding_session_access.sql:89-90`) |
| Комментарии | Отключённая группа доступна, если она — группа обсуждения включённого канала. Связь берётся из `ChannelFull.linked_chat_id` (симметрична: у супергруппы это ID канала) |
| Где действует | Три точки: входящие события, разрешение чата в инструментах, таймеры. Одна проверка по ID чата |
| Прогрев | Не подчиняется настройке: диалоги между мимиками — служебные, иначе несвязанная настройка молча ломает защиту аккаунта |
| Список чатов в интерфейсе | Живые диалоги из клиента запущенного рантайма. Остановленный агент: список недоступен (409), сохранённые отключения при этом действуют |
| Сохранение | Та же форма «Настройки»: dirty → «Сохранить изменения» → merge в settings → `agentsApi.reload()` |
| Пресеты, онбординг | Не затрагиваются |

## Контекст (по коду)

- Все инструменты, адресованные чату, разрешают получателя через
  `TelegramToolbox._resolve_peer` (`telegram_tools.py:505`) — единая точка. Через неё же
  разрешаются и люди (`user`, `users`, `bot_username`), их проверять не нужно.
- Инструменты создаются в `AgentManager._build_runtime_with_memory` и `_build_runtime`
  (`manager.py:327,364`) вместе с рантаймом; общие объекты (`send_window`, `media_refs`)
  передаются в оба.
- Конфиг рантайма — `AgentRuntimeConfig` (`agent_runtime.py:122`); настройки из
  `agents.settings` разбирает `DatabaseAgentStore.get_runtime_config`
  (`database_agent_store.py:260-303`) тем же приёмом, что `enabled_tools` и
  `first_comment` (`core/tool_config.py`, `core/first_comment.py`).
- Входящее проходит `_dispatch_incoming` (`agent_runtime.py:1859`): проверка мьюта,
  @SpamBot, вердикт прогрева, затем ход. Первый комментарий — `_handle_channel_post`
  (`:1303`), регистрируется раньше ИИ-ветки.
- Таймеры: `set_wakeup_timer` (`telegram_tools.py:2594`) пишет peer строкой, без
  разрешения; срабатывают в `_check_and_trigger_timers` (`agent_runtime.py:2149`).
  Статусы таймера ограничены `pending/running/succeeded/failed`.
- `join_channel` по инвайт-ссылке не проходит через `_resolve_peer`
  (`telegram_tools.py:2291-2343`): ID чата до вступления неизвестен.
- Telethon 1.43.2: `client.get_peer_id` приводит и `InputPeerSelf` (в отличие от
  `utils.get_peer_id`, который на нём падает); `GetFullChannelRequest(...).full_chat.linked_chat_id`
  уже используется в `join_channel_discussion` (`telegram_tools.py:2143`).

## Бэкенд

### Политика (`src/mimic42/core/chat_access.py`)

```python
def parse_disabled_chats(raw: Any) -> frozenset[int]: ...

class ChatAccess:
    def __init__(self, disabled: frozenset[int], linked_channel: LinkedChannelLookup): ...
    async def allows(self, chat_id: int) -> bool: ...
```

- `parse_disabled_chats`: не список → пустое множество и запись в лог; в списке остаются
  только `int` (не `bool`), остальное отбрасывается. Нечитаемая настройка не должна ни
  ронять агента, ни отключать чаты случайно.
- `allows`: ID не в `disabled` → `True`. Иначе для супергруппы (`chat_id < -10**12`) —
  спросить `linked_channel(chat_id)` и вернуть `True`, если связанный канал не отключён.
  Любой другой тип отключённого чата → `False`.
- `LinkedChannelLookup` — `Callable[[int], Awaitable[int | None]]`, возвращает marked ID
  связанного канала. Результат кешируется (TTL 1 час); сбой запроса считается «не
  связана» (закрыто по умолчанию) и в кеш не попадает.
- Пустой `disabled` → `ChatAccess` не создаётся (`None`): ни одной проверки, ни одного
  запроса у существующих агентов.

Реализация поиска связи — `src/mimic42/integrations/chat_directory.py` (Telethon):
`GetFullChannelRequest` по группе и перевод ID в marked-форму. Там же листинг диалогов
для API.

### Конфиг и сборка

- `AgentRuntimeConfig.disabled_chats: frozenset[int] = frozenset()`; `get_runtime_config`
  читает `agent.settings.get("disabled_chats")` через `parse_disabled_chats`.
- `ChatAccess` строит менеджер (по клиенту рантайма) и передаёт и рантайму, и
  `build_telegram_langchain_tools`/`TelegramToolbox` — как `send_window`.

### Входящие

- `_dispatch_incoming`: сразу после вердикта прогрева, только когда вердикт `None`
  (обычная переписка, не диалог с другим мимиком), — `await access.allows(chat_id)`;
  при `False` — выход с записью в лог. В ленту активности ничего не пишется (как у мьюта).
- `_handle_channel_post`: пост отключённого канала не получает первого комментария.
  Канал вещательный, поэтому проверка — по ID без поиска связи.

### Инструменты

- Новый `TelegramToolbox._resolve_chat(peer, as_input=True)` = `_resolve_peer` + проверка:
  ID берётся через `client.get_peer_id` (разрешает «me»/`InputPeerSelf`), отказ —
  исключение `ChatDisabledError` с текстом для модели «Чат недоступен: он отключён в
  настройках агента». `_tool_failure` уже отдаёт его как `success: false` с
  `error_code: "ChatDisabledError"`.
- Вызовы `_resolve_peer`, где параметр — чат, заменяются на `_resolve_chat`: все `peer`,
  `from_peer`/`to_peer`, `channel`, `broadcast`/`group`, `target` в `start_bot`, `peers`
  в архивации, папки (`include/exclude/pinned_peers`). Люди (`user`, `users`,
  `bot_username`, `get_profile`, контакты, приватность) остаются на `_resolve_peer`.
- `get_dialogs`: отключённые чаты скрыты; чтобы вернуть `limit` доступных, диалоги
  читаются порциями, пока не наберётся лимит.
- `get_chat_folders` и `get_common_chats`: отключённые чаты убираются из выдачи.
  `create_or_update_chat_folder` перезаписывает папку целиком, а скрытых пиров агент не
  видел, поэтому пиры существующей папки, закрытые от агента, добавляются обратно.
- `join_channel`: публичное имя и ID проходят `_resolve_chat`. Вступление по
  инвайт-ссылке не проверяется: ID чата заранее неизвестен, а вступивший чат — новый и
  потому доступен.
- `set_wakeup_timer`: при заданном `ChatAccess` peer разрешается и проверяется; ошибка
  разрешения — отказ инструмента (иначе доступность нельзя подтвердить). Без `ChatAccess`
  поведение прежнее.
- Инструменты по `media_id` (`view_image`, `transcribe_voice_note`, `read_document_file`,
  `set_profile_photo`) не проверяются: `media_id` пришёл из контекста, который агент уже
  видел.

### Таймеры

`_check_and_trigger_timers`: при заданном `ChatAccess` peer таймера разрешается и
проверяется; для недоступного чата ход не запускается, таймер получает `failed`, событие
`timer.failed` с `error_code: "ChatDisabledError"`. Миграция статусов не нужна.

## API

`GET /api/v1/agents/{agent_id}/chats` (только владелец) → `list[ChatItem]`:

```json
{ "id": -1001234567890, "title": "…", "username": "name|null",
  "kind": "channel|group|private", "discussion_of": -1009876543210 }
```

- `kind`: вещательный канал → `channel`, супергруппа и обычная группа → `group`,
  человек и бот → `private`. «Избранное» — `private` с названием «Избранное».
- `discussion_of` — marked ID канала, если это его группа обсуждения (супергруппа с
  `has_link`; связь через `linked_chat_id`, параллелизм запросов ограничен, результат
  кешируется общим кешем `ChatAccess`). Не удалось узнать — `null`.
- Источник — `iter_dialogs` клиента запущенного рантайма: основной список и архив
  двумя явными обходами (`folder=0` и `folder=1`: Telegram отдаёт архив папкой 1);
  сам список кешируется в рантайме на 10 секунд: кнопка «Обновить список» должна
  показывать новые чаты, а кеш только гасит повторные запросы.
- Агент не запущен — `409` с понятным сообщением; нет агента или чужой — как у соседних
  эндпоинтов.
- В менеджер добавляется `list_chats(agent_id)`; эндпоинт опирается на протокол вроде
  `WarmupControl` (`app.py:116`), поскольку подделки менеджера в тестах им не обладают.

## Интерфейс

Секция «Чаты и каналы» в `TabSettings` после «Инструментов»
(`frontend/src/components/agent/ChatsSettings.tsx`):

- Заголовок со счётчиком «Доступно N из M» и кнопкой «Включить все» — очищает
  `disabled_chats`.
- Поиск по названию и @username; при поиске группы раскрываются.
- Три сворачиваемые группы: «Каналы», «Группы», «Личные». В заголовке — счётчик «N из M»
  и переключатель всей группы; он меняет только известные сейчас чаты, новые чаты всё
  равно включаются автоматически (подсказка под заголовком секции). Внутри группы по
  умолчанию показаны первые 100 строк, дальше — «Показать ещё».
- Строка чата: название, @username, переключатель (`role="switch"`, имя — название чата).
  Группа обсуждения включённого канала показана включённой и заблокированной с
  подсказкой «Комментарии канала «X»: доступна, пока канал включён»; после отключения
  канала действует собственное состояние группы. Если канала нет среди диалогов (в
  группу вступили напрямую), группа не блокируется: её переключатель меняет ID группы и
  канала вместе — иначе правило доступа отпустило бы её, а выключить было бы нечем; канал
  отдельной строкой в «Нет в списке диалогов» не показывается.
- Отключённые ID, которых нет в живом списке (вышел из чата), показываются в отдельном
  блоке «Нет в списке диалогов» с возможностью включить обратно.
- Агент не запущен — вместо списка пояснение «Запустите агента, чтобы увидеть чаты» и
  блок с уже отключёнными ID; сохранённые отключения остаются в силе.
- Состояние формы: `disabled_chats: number[]`. Валидация в `validators.ts`:
  `z.array(z.number().int()).max(20000).optional()`. Чтение и запись —
  `readDisabledChats`/`mergeDisabledChats` в `frontend/src/lib/chats/` по образцу
  `lib/tools/agentTools.ts`: пустой список удаляет ключ из settings.
- Хук `useAgentChats(agentId)` (TanStack Query) берёт `GET …/chats`; ошибка 409 —
  штатное состояние «агент не запущен», а не сбой.
- Каталог ошибок ленты (`errorCatalog.ts`) получает `ChatDisabledError` с русским текстом.
- Оформление и поведение — по скиллу Impeccable (UI).

- Playwright (`tests/e2e/test_agent.py`): отключить чат, сохранить, перезагрузить
  страницу — состояние сохранилось. Прогон — один раз в конце, как у остальных тестов.
- Живая проверка в Telegram (`real_tg`): отключённый чат не получает ответа, включённый —
  получает. Берёт замок `RealTelegramLock`.

## Чего не делаем

- Режима «новые чаты выключены» и белого списка: правило доступа одно.
- Списка чатов для остановленного агента (снимок диалогов в БД, временный клиент по
  строке сессии): второе подключение той же сессии рискует её отзывом.
- Ограничений на людей и контакты (`get_profile`, `add_contact`, приватность, стикеры,
  папки целиком): настройка управляет чатами.
- Стирания памяти: воспоминания Mem0 и история сессии из отключённого чата остаются.
- Ограничений на ручной триггер из дашборда (`POST …/trigger`): это явная команда
  владельца.
- Ограничения на прогрев и на вступление по инвайт-ссылке (см. «Принятые решения» и
  «Инструменты»).
- Настройки в пресетах и онбординге.
