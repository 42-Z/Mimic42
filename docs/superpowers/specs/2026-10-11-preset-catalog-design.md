# Каталог пресетов (issue #67) — дизайн

## Обзор

Вкладка «Пресеты» в меню дашборда: витрина выложенных пресетов, свои пресеты с
черновиками и избранное. Пользователь сохраняет чужой пресет в избранное — он
появляется в меню выбора у мимиков, рядом с официальными. Свой пресет создаётся
как черновик, выкладывается всем сразу без модерации, снимается с витрины и
удаляется. Пресет = название, короткое описание, промпт для Мимика, опционально
набор включённых инструментов.

## Согласованные решения

- Магазин без модерации: черновик виден только автору, «Выложить» сразу
  показывает его всем, «Снять» убирает с витрины.
- Меню у мимика: официальные четыре + свои (черновики и выложенные) +
  избранное. Официальные и свои в избранное не кладутся — они и так в меню.
- Правка выложенного пресета сразу видна всем, у кого он в избранном. Уже
  применённый характер мимика сам не меняется, пока пресет не применят снова.
- Снятие с витрины и удаление не трогают чужие сохранённые копии: в избранном
  остаётся замороженная копия на момент снятия, которую можно только применять.
- Копия не превращается в свой черновик: править и выкладывать её нельзя.
- Хранение — всё в `prompt_presets`, официальные четыре строки не трогаются.

## Схема данных

### `prompt_presets`

Добавляются две колонки:

- `owner_id uuid references public.profiles(id) on delete cascade` — у
  официальных строк `null`; у пользовательских всегда владелец.
- `published_at timestamptz` — `null` у официальных и у черновиков; время
  выкладки у витринных.

Уникальный `slug` сохраняется: официальные хранят свои (`rage_comments` и
прочие), пользовательским `slug` присваивает before-insert триггер
(`u_<uuid>`), клиент слаг не передаёт и не меняет. `is_active` пользовательских
строк всегда `true`; снятие с витрины — только `published_at = null`, флага
«выключен» у своих нет.

Гранты колонок:

- `insert (owner_id, title, summary, body, settings)` — `published_at` и `slug`
  не выдаются: черновик создаётся без витрины, слаг ставит триггер.
- `update (title, summary, body, settings, published_at)` — владельца, слаг и
  `is_active` клиент не меняет.
- `delete` — свои строки.

RLS-политики для `authenticated`:

- `select`: `owner_id is null and is_active` (официальные) или
  `owner_id = auth.uid()` (свои, включая черновики) или
  `published_at is not null` (витрина).
- `insert` with check: `owner_id = auth.uid() and published_at is null`.
- `update` using и with check: `owner_id = auth.uid()`.
- `delete` using: `owner_id = auth.uid()`.

Триггеры на `prompt_presets` (все `security definer` с фиксированным
`search_path`, чтобы работать поверх RLS):

- before insert: `owner_id = auth.uid()` обязателен (официальную строку без
  владельца создать нельзя), `published_at = null`, `is_active = true`,
  `slug = 'u_' || new.id`, `owner_id` пустой запрещён.
- before update/delete: строка с `owner_id is null` недоступна из сессии
  пользователя — официальные нельзя изменить и удалить даже при ошибке в
  политике.
- before update: изменение `owner_id` или `slug` в строке владельца запрещено.
- before update: если `published_at` меняется с значения на `null` (снятие) —
  заморозить избранное (см. ниже). Публикация (`null` → значение) просто
  проходит.

### `preset_favorites`

```sql
create table public.preset_favorites (
    id uuid primary key default gen_random_uuid(),
    owner_id uuid not null references public.profiles(id) on delete cascade,
    preset_id uuid references public.prompt_presets(id) on delete cascade,
    frozen_title text,
    frozen_summary text,
    frozen_body text not null,
    frozen_settings jsonb check (frozen_settings is null or jsonb_typeof(frozen_settings) = 'object'),
    frozen_at timestamptz,
    created_at timestamptz not null default now(),
    updated_at timestamptz not null default now(),
    unique (owner_id, preset_id),
    constraint preset_favorites_have_source_or_snapshot
        check (preset_id is not null or frozen_at is not null)
);
```

- `preset_id` указывает на живой витринный пресет, снимки пустые — избранное
  показывает текущую версию.
- `frozen_*` + `frozen_at` — замороженная копия, `preset_id = null`.

Заморозка — триггеры на `prompt_presets`:

- снятие с витрины (update `published_at` значения → `null`): для каждого
  избравшего копировать `title/summary/body/settings` в `frozen_*`, ставить
  `frozen_at = now()` и обнулять `preset_id`.
- удаление: то же самое в before delete, после чего строка пресета удаляется
  каскадом (ссылок на `preset_id` уже нет).
- повторная выкладка оживляет только новые записи: старая замороженная копия
  остаётся копией навсегда, тот же пресет можно сохранить в избранное ещё раз —
  появятся обе записи (замороженная и живая).

RLS `preset_favorites` для `authenticated`:

- `select`: `owner_id = auth.uid()`.
- `insert` with check: `owner_id = auth.uid()` и пресет существует, выложен,
  не официальный (`owner_id` пресета не `null`) и не свой.
- `update` — политики нет: заморозку делает только триггер.
- `delete`: `owner_id = auth.uid()` — убрать из избранного можно всегда,
  включая замороженную копию.

### Имена авторов

`profiles` читает только владелец, почту чужую открывать нельзя. Витринное имя
автора — отдельное представление:

```sql
create view public.preset_authors as
select distinct pp.owner_id as id, pr.display_name
from public.prompt_presets pp
join public.profiles pr on pr.id = pp.owner_id
where pp.published_at is not null;
```

Вид исполняется с правами владельца (по умолчанию в Postgres 15 вид не
`security_invoker`), поэтому RLS профилей не применяется; наружу идут только
`display_name` авторов выложенных пресетов. `grant select` для
`authenticated`. Пустое имя — показывать «Без имени».

## Фронтенд

**Страница** `frontend/src/app/(dashboard)/presets/page.tsx` + пункт «Пресеты» в
`mainNav` сайдбара (`components/layout/Sidebar.tsx`, иконка Library).

Три вкладки страницы:

- **Магазин** — официальные активные + все чужие выложенные, поиск по названию
  и описанию (клиентский фильтр). Карточка: название, описание, автор (из
  `preset_authors`), метка инструментов, кнопка «В избранное» / «В избранном».
  Официальные кнопки избранного не имеют.
- **Мои** — свои черновики и выложенные. Карточка с действиями: редактировать,
  выложить / снять, удалить. Метки «Черновик» / «В магазине».
- **Избранное** — сохранённые чужие пресеты: живые и замороженные копии
  (метка «Копия»), кнопка убрать из избранного.

**Создание и редактирование** — модалка `PresetEditorDialog` (файл
`frontend/src/components/presets/PresetEditorDialog.tsx`): поля «Название»,
«Короткое описание», «Промпт» (textarea), секция инструментов. Секция
инструментов переиспользует компонент, которым страница агента редактирует
`enabled_tools` (группы, поиск, «Включить все», сохранение неизвестных имён) —
экстракт существующей секции из `TabSettings` в общий
`components/tools/ToolSettingsSection`, без смены поведения. Пустой промпт
запретить (кнопка сохранения недоступна), подсказка на русском.

**Меню у мимика** `PresetPickerDialog` (`components/agent/PresetPicker.tsx`)
остаётся одной модалкой со списком, список делится на секции «Официальные»,
«Мои», «Избранное». Источник — расширенный `usePromptPresets` (один select уже
возвращает официальные, свои и витрину) плюс `useFavorites`. Живое избранное
читает текущую версию пресета, замороженное — `frozen_*`. Применение работает
как раньше: кладёт тело и настройки в форму, сохранение — на существующих
кнопках; второго подтверждения замены характера это не добавляет.

**Хуки** (`frontend/src/hooks/`):

- `usePromptPresets` — как сейчас, без изменений (select уже покрывает все три
  источника).
- `usePresetFavorites` — select из `preset_favorites` (свои строки), join на
  `prompt_presets` не нужен: живые записи соединяются на клиенте по `preset_id`.
- `usePresetMutations` — create / update / publish / unpublish / delete /
  favorite / unfavorite; после каждой мутации инвалидация
  `queryKeys.presets` и ключа избранного.

**Состояния**: скелетоны при загрузке, текст ошибки с повтором, пустые вкладки
со своими строками («Своих пресетов пока нет», «В избранном пока ничего нет»).
Реалтайм не обязателен: обновление по инвалидации после действий.

## Бэкенд

Не трогается: рантайм читает `soul_prompt` агента, каталог инструментов на
фронте уже синхронизирован. Правки только в миграциях и на фронте.

## Тесты

- `tests/integration/test_prompt_presets.py` (маркер `db`, расширяется):
  - официальные строки по-прежнему только читаются;
  - `authenticated` создаёт черновик (`owner_id = auth.uid()`), не может
    создать строку без владельца, с чужим `owner_id` или сразу выложенную;
  - не может обновить официальную строку и поменять `owner_id` своей;
  - чужой черновик не читается, чужой выложенный читается;
  - снятие с витрины замораживает избранное (триггер), повторная выкладка
    оживляет только новую запись;
  - удаление пресета замораживает избранное и оставляет строку favorites;
  - уникальность `(owner_id, preset_id)`, повторное сохранение живого пресета
    после заморозки создаёт вторую запись;
  - в избранное нельзя положить официальный, свой и невитринный пресет.
- `bun test`:
  - `PresetPicker` — секции, живое и замороженное избранное, применение без
    изменений;
  - хук мутаций — инвалидация кеша, тексты ошибок;
  - редактор — валидация пустого промпта, секция инструментов (экстракт не
    сломал страницу агента: существующие тесты `TabSettings` остаются
    зелёными);
  - страница каталога — вкладки, поиск, карточки, действия.
- Playwright `tests/e2e/test_preset_catalog.py`:
  - создать пресет, выложить, убедиться в «Магазине»;
  - снять с витрины — исчез из магазина, остался в «Моих»;
  - сохранить в избранное, увидеть в меню у мимика в секции «Избранное»;
  - редактор: пустой промпт не сохраняется.

Миграции применяются `supabase db push`, типы фронта —
`bun run generate:types`.
