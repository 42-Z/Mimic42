# Дизайн: каталог пресетов

Issue: https://github.com/42-Z/Mimic42/issues/67
Дата: 2026-10-11

## Цель

Превратить справочник пресетов промптов (issue #68, #37) в каталог: отдельная вкладка в
меню со списком пресетов, избранное, собственные пресеты пользователя и их публикация для
всех. Пресет — название, краткое описание, промпт для Мимика и опционально настройки
инструментов (`enabled_tools`).

Применение пресета не меняется: текст и набор инструментов копируются в форму агента, дальше
это обычные данные пользователя без связи с пресетом.

## Принятые решения

| Вопрос | Решение |
|---|---|
| Что видно в окне выбора у Мимика | Наши четыре пресета всегда + избранное + собственные пресеты. Остальное из каталога — только через избранное |
| Публикация | Сразу, без модерации. Автор может снять с публикации или удалить. Скрыть чужой пресет мы можем через `is_active = false` под `service_role` |
| Автор в карточке | Не показываем. `profiles.display_name` по умолчанию — часть почты, публиковать его без согласия нельзя. У своих пресетов помечаем «Ваш» |
| Приватность пресета | Новый пресет личный (`is_published = false`): виден и применим только автору, пока тот не опубликует |
| Ограничения | Не более 50 собственных пресетов на пользователя; длины полей — в CHECK, зеркально в zod |
| Бэкенд | Не трогаем. Каталог читается и пишется из браузера напрямую под RLS, как и прежний справочник |

## Схема данных

Одна миграция `supabase/migrations/<timestamp>_preset_catalog.sql` (имя создаёт
`supabase migration new`).

`public.prompt_presets` получает:

- `owner_id uuid references public.profiles(id) on delete cascade` — `null` у наших пресетов;
- `is_published boolean not null` — у существующих строк `true`, у новых по умолчанию `false`;
- `slug` перестаёт быть обязательным: он нужен только нашим пресетам (миграции правят их
  `update ... where slug = ...`), у пользовательских его нет;
- CHECK: нашему пресету нужен slug и публикация, пользовательскому slug запрещён; длины
  `title` ≤ 80, `summary` ≤ 200, `body` ≤ 50 000 (как у `soul_prompt`); размер `settings`
  ≤ 16 КиБ;
- частичный индекс по `owner_id` — по нему идут политики и каскад.

Новая таблица `public.prompt_preset_favorites (user_id, preset_id, created_at)`, первичный ключ
`(user_id, preset_id)`, оба внешних ключа с `on delete cascade`, индекс по `preset_id` для
каскада.

### Права и RLS

Права по умолчанию на проекте выданы `anon` и `authenticated` на всё (включая `TRUNCATE`), а
прежняя миграция их не отзывала. Здесь: `revoke all ... from anon, authenticated`, затем точечно.

| Таблица | `authenticated` |
|---|---|
| `prompt_presets` | `select`; `insert (owner_id, title, summary, body, settings, is_published)`; `update (title, summary, body, settings, is_published)`; `delete` |
| `prompt_preset_favorites` | `select`; `insert (user_id, preset_id)`; `delete` |

Политики — по одной на операцию, всегда `to authenticated` и `(select auth.uid())`:

- `prompt_presets` select: `is_active and (is_published or owner_id = uid)`;
- insert: `owner_id = uid` и у пользователя меньше 50 пресетов; `slug`, `sort_order`, `is_active`
  клиент не задаёт вовсе — их закрывают колоночные гранты;
- update: `owner_id = uid` в `using` и `with check` (передать пресет другому нельзя);
- delete: `owner_id = uid`;
- `prompt_preset_favorites` select/delete: `user_id = uid`; insert: `user_id = uid` и пресет
  виден пользователю (подзапрос идёт под его RLS, поэтому в избранное нельзя положить чужой
  личный пресет).

Политики избранного читают `prompt_presets`, а политики `prompt_presets` избранное не читают, так
что цикла (`42P17`) нет.

## Фронтенд

**Данные** (`frontend/src/hooks/usePromptPresets.ts`, остальное в `frontend/src/lib/presets/`):

- `usePromptPresets()` — все видимые пользователю активные пресеты (RLS отсекает чужие личные);
- `usePresetFavorites()` — множество `preset_id`; `useTogglePresetFavorite()` с оптимистичным
  обновлением и откатом;
- `useSavePreset()` / `useDeletePreset()` — запись собственных пресетов;
- чистые функции без react-query, чтобы проверять их тестами: порядок (наши по `sort_order`,
  затем пользовательские от новых к старым), поиск, отбор для окна выбора
  (`pickablePresets` = наши ∪ избранное ∪ свои).

**Страница `/presets`**, пункт «Каталог пресетов» в боковом меню. Три раздела: «Каталог»
(все видимые), «Избранное», «Мои». Карточка: название, описание, число включённых инструментов,
пометки «Наш» / «Ваш» / «Личный». Действия: звезда избранного (у наших пресетов её нет — они
и так всегда в выборе), «Посмотреть» (полный текст в модальном окне). В «Мои»: создать, править,
удалить, переключатель публикации. Форма пресета — название, описание, промпт и переиспользуемый
`ToolsSettings` для необязательного набора инструментов.

**Окно выбора** (`PresetPicker`) показывает `pickablePresets`. Если список пуст — пустое
состояние со ссылкой на каталог. Поведение «Применить» (подтверждение перед заменой, перенос
`enabled_tools`) не меняется. Выбор в окне идёт по `id`, а не по `slug`.

## Тесты

- Интеграционные (`pytest -m db`, роль `authenticated` с клеймами двух пользователей): личный
  пресет виден только автору, публикация открывает его другим, чужой пресет нельзя править,
  удалять и переопределить владельца, `slug`/`sort_order`/`is_active` клиент не задаёт, лимит 50,
  избранное чужого личного пресета отклоняется, избранное видит только владелец, наши четыре
  по-прежнему читаются и не пишутся. Очистка слота (`purge_slot_data`) убирает пресеты и избранное
  тестовых персон.
- `bun test`: порядок и отбор для окна выбора, схема формы, переключение избранного, карточки и
  страница, окно выбора с пустым и непустым списком.
- Playwright: пользователь создаёт пресет, публикует, добавляет в избранное и применяет его у
  агента.

## Что не делаем

- Модерацию, жалобы, админский интерфейс, премодерацию.
- Имя автора и профили авторов.
- Счётчики добавлений и рейтинги: избранное читается только владельцем, а общий счёт потребовал
  бы `security definer` функции или денормализации.
- Связь агента с пресетом (`preset_id`), синхронизацию правок с уже применёнными текстами.
- Импорт и экспорт, версии пресетов, теги и категории.
- Изменения в Python.

## После слияния

Пайплайн не мигрирует продовую базу (`deploy/README.md`): миграцию надо вручную применить на проде
(`supabase db push`) до или вместе с деплоем, иначе страница каталога и окно выбора на проде
получат ошибку чтения несуществующих колонок.
