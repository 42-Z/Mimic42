# Mimic 42

Максимально реалистичный ИИ-агент, который иммитирует человека

Агент взаимодействует с миром через Telegram

Этот нейробот создан, чтобы полноценно и натурально упралять Telegram

## Задумка

### Агентская сторона

- Агент на LangChain с инструментами
- Долгосрочная память на Mem0 
- Сессия целиком сохраняется в базу данных - сообщения и использования инструментов не теряются

Он должен общаться живо, как человек

Должен быть базовый промпт (объясняющий, что агент делает) + пользовательский (темперамент и стиль)

### Чат сторона

- Инструменты, которые релизуют ВСЕ функции для использования Telegram
- ТГ не через бота, а через юзербота на Telethon
- Задействовать каждый метод Telethon в качестве инструемнта для агента

Необходимо сделать широкий спектр инструментов, чтобы нейросеть могла делать буквально все

### Дэшборд сторона

- Приложениие многопользовательское (каждый может создать своего агента)
- Веб-сайт с авторизацией 
- Настраивается: Характер (SOUL.md) API токен и т.д.

Сначала идет онбординг воркфлоу, где пошагово задается характер и авторизация в сессию ТГ

Затем открывается статистика с действиями бота  

## Разработка

### Правила

- Используй Uv, Ruff и Ty, Bun, Supabase CLI
- Обязательно читай документацию библиотек, с которыми работаешь
- Используй Git и делай изменения в отдельной ветке с последующим PR
- Делай коммиты сам
- Используй Субагентов параллельно, когда задачи независимы и не разделяют состояние. Если место в плане допускает параллельную работу — запускай несколько Субагентов одновременно. Если задача последовательная или требует общего контекста — делай инлайн
- не используй эмодзи вместо иконок, используй икон паки или делай иконки сам в .svg, и не добавляй mock (затычки) данные в бд, и сразу делай до конца, если надо сделать условно чтобы записывалась таблица лидеров, ты сразу делаешь ее рабочей и без mock данных, в базе данных не должно быть того что записал туда ты, а если надо что то протестить, то ты добавляешь эти данные, смотришь работает или нет, и удаляешь

### Стек

### Поиск по документации

Всегда предпочитай чтение документации вместо инпекции через скрипты

Ты должен читать документацию по каждому методу, классу, свойству, которое используешь

Открывай сайт документации, а не просто используй разовый веб-поиск

### Тестовый профиль

На сервере продакшн база данных с реальными агентами, а на кмпьютере тестовая база, чтобы запущенные одновременно Мимики не мешали друг другу

### Баги

Если агент не работает, выбрасывается исключение или случается какое-то неожиданное поведение, их надо исправить

Ты должен посмотреть логи, историю сессии, выяснить обстоятельства, и выяснить из-за чего происходит конкретная ошибка

Источником ошибки могли быть не только твои изменения, но и старые - все надо приводить к рабочему состоянию

Не пытайся сделать заплатки или костыли, а решай все окончательно

### CI и PR

- После каждого коммита и пуша проверяй статус CI через `gh pr checks <номер PR>`. Не жди, пока скажут — сам проверяй
- Если CI упал — смотри логи через `gh run view <run_id> --log-failed`, находи причину и фикси
- Следи за статусом PR: `gh pr view <номер> --json mergeable,mergeStateStatus,reviews`. PR должен быть `MERGEABLE` и `mergeStateStatus: CLEAN`
- Если есть замечания от ревьюера — исправляй их сразу, не жди напоминаний
- Не оставляй ветку в состоянии, когда CI красный или PR заблокирован — доводи до конца
